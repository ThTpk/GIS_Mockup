# GeoCore GIS — ต้นแบบหน้าจอระบบสารสนเทศภูมิศาสตร์

ต้นแบบหน้าจอ (mockup) สำหรับอธิบายขอบเขตงานพัฒนาระบบสารสนเทศภูมิศาสตร์ขององค์กรปกครองส่วนท้องถิ่น
เป็นเว็บแบบ static ไม่ต้องติดตั้งเซิร์ฟเวอร์ และเปิดบนมือถือได้

ต้นแบบแยกเป็นสองส่วนที่ไม่ปะปนกัน

| ส่วน | เนื้อหา | จำนวน |
|---|---|---|
| **ตัวอย่างระบบงาน** | หน้าจอที่เจ้าหน้าที่ใช้ทำงานจริง จัดวางอย่างระบบที่ใช้งานได้จริง ไม่มีคำอธิบายการออกแบบปะปน | 16 หน้า |
| **รายละเอียดระบบงาน** | สถาปัตยกรรม กฎการทำงานรายหน้าจอ ความครอบคลุมตามขอบเขตงาน และเอกสารการออกแบบ | 7 หน้า |

ทั้งสองส่วนเชื่อมถึงกันด้วยปุ่มที่แถบบน หน้าจอใช้งานมีปุ่ม **รายละเอียดระบบ** ที่เปิดคำอธิบาย
ของหน้าจอนั้นในแท็บใหม่ และหน้าเอกสารมีปุ่ม **หน้าจอใช้งานระบบ** กลับมาที่ระบบงาน
`index.html` เป็นหน้าทางเข้า แยกทางไปยังสองส่วนนี้

> ข้อมูลทั้งหมดในต้นแบบเป็น **ข้อมูลสมมุติ** ชื่อระบบ หน่วยงาน และตัวเลขเป็นค่าตัวอย่างเพื่อการสาธิต
> ไม่ใช่ข้อมูลของหน่วยงานใด

## การเปิดดู

### เปิดจากเครื่อง

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ (ไม่ใช่ดับเบิลคลิกไฟล์) เพราะหน้าจอโหลดสคริปต์ร่วมกัน

```bash
python -m http.server 8080
```

แล้วเปิด `http://localhost:8080`

### เผยแพร่บน GitHub Pages

1. สร้าง repository ใหม่บน GitHub แล้วนำไฟล์ทั้งหมดในโฟลเดอร์นี้ขึ้นไป

   ```bash
   git init
   git add .
   git commit -m "GeoCore GIS mockup"
   git branch -M main
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```

2. ไปที่ **Settings → Pages** เลือก **Source: Deploy from a branch**
   แล้วเลือก branch `main` และโฟลเดอร์ `/ (root)`

3. รอประมาณ 1 นาที เว็บจะเผยแพร่ที่ `https://<user>.github.io/<repo>/`

ไฟล์ `.nojekyll` มีไว้ให้ GitHub Pages เสิร์ฟไฟล์ทุกไฟล์ตามที่เป็น ไม่ผ่านตัวประมวลผล Jekyll

## กลุ่มผู้ใช้งาน

ระบบแยกสิทธิ์เป็น 3 กลุ่มหลักตามลักษณะงาน และเพิ่มกลุ่มผู้ดูแลระบบสำหรับงานตั้งค่า

| กลุ่ม | อ่านข้อมูล | ป้อนข้อมูล | อนุมัติ | ส่งออก/เผยแพร่ | ตั้งค่าระบบ |
|---|---|---|---|---|---|
| ผู้อ่านข้อมูล (viewer) | ทั้งหมด | — | — | แผนที่/ตาราง | — |
| ผู้ป้อนข้อมูล (editor) | เฉพาะของตน | ได้ | — | — | — |
| ผู้ใช้งานทั้งสองสิทธิ์ (both) | ทั้งหมด | ได้ | ได้ | ได้ | — |
| ผู้ดูแลระบบ (admin) | ทั้งหมด | ได้ | ได้ | ได้ | ได้ |

**สลับกลุ่มสิทธิ์ได้จากปุ่มมุมขวาบนของทุกหน้า** เพื่อดูว่าหน้าจอเปลี่ยนไปอย่างไร

การจำกัดสิทธิ์บังคับ 3 ระดับ

1. **เมนู** — หน้าที่กลุ่มสิทธิ์นั้นไม่มีสิทธิ์อ่าน จะแสดงเป็นสีจางพร้อมไอคอนกุญแจและกดไม่ได้
2. **ลิงก์ภายในหน้า** — การ์ดและปุ่มที่ชี้ไปยังหน้าเหล่านั้นถูกปิดเช่นกัน
3. **ตัวหน้าเอง** — เปิด URL ตรงก็ไม่เห็นเนื้อหา ระบบแสดงหน้าแจ้งว่าไม่มีสิทธิ์เข้าถึง
   พร้อมบอกว่ากลุ่มใดเข้าได้และเหตุผล

ส่วนหน้าที่เปิดได้แต่แก้ไขไม่ได้ ปุ่มที่เกินสิทธิ์จะถูกซ่อน และมีแถบเตือนสิทธิ์อ่านอย่างเดียวที่ด้านบน
ดูตารางสรุปได้ที่หน้า **ผู้ใช้งานและสิทธิ์**

สิทธิ์ที่เลือกเก็บไว้ใน `localStorage` ของเบราว์เซอร์ ล้างได้ด้วยการล้างข้อมูลเว็บไซต์

## ชั้นข้อมูล 10 ชั้น

| รหัส | ชั้นข้อมูล | รูปทรง | ที่มา |
|---|---|---|---|
| L01 | ถนน | MultiLineString | สำรวจใหม่ |
| L02 | ไฟส่องสว่าง | Point | สำรวจใหม่ |
| L03 | กล้องโทรทัศน์วงจรปิด | Point | สำรวจใหม่ (ข้อมูลอ่อนไหว) |
| L04 | สะพาน | Point | สำรวจใหม่ |
| L05 | แหล่งน้ำและระบบประปา | Point / Line / Polygon | สำรวจใหม่ |
| L06 | ทางระบายน้ำและจุดปัญหาน้ำเสีย | Line / Point | สำรวจใหม่ |
| L07 | พื้นที่สาธารณะและจุดอัตลักษณ์ชุมชน | Polygon / Point | สำรวจใหม่ |
| L08 | แนวเขตพื้นที่ศึกษาและพื้นที่คลาดเคลื่อน | MultiPolygon | สำรวจใหม่ |
| L09 | แนวเขตที่ดิน | MultiPolygon | ชั้นข้อมูลเดิม (เชื่อมโยง) |
| L10 | สิ่งปลูกสร้าง | MultiPolygon | ชั้นข้อมูลเดิม (เชื่อมโยง) |

ทุกชั้นข้อมูลใช้ชุดฟิลด์มาตรฐานเดียวกัน 21 ฟิลด์ ครอบคลุมรหัสรายการไม่ซ้ำ แหล่งข้อมูล
วันที่สำรวจ หน่วยงานรับผิดชอบหรือสถานะรอยืนยัน และคำอธิบายข้อมูล

## การนำเข้าข้อมูล

ระบบนำเข้าข้อมูลเชิงพื้นที่ได้ทั้งสามรูปทรง จากไฟล์สามรูปแบบหลัก

| รูปแบบไฟล์ | นามสกุล | รูปทรงที่รองรับ | ระบบพิกัด |
|---|---|---|---|
| GeoJSON | `.geojson` `.json` | Point · LineString · Polygon และชนิด Multi | อ่านจาก CRS member (ค่าตั้งต้น EPSG:4326) |
| KML / KMZ | `.kml` `.kmz` | Point · LineString · Polygon · MultiGeometry | EPSG:4326 ตามข้อกำหนดของรูปแบบ |
| Shapefile | `.zip` (มี `.shp` `.shx` `.dbf` `.prj`) | Point · PolyLine · Polygon · MultiPoint | อ่านจากไฟล์ `.prj` |
| GeoPackage | `.gpkg` | ทุกชนิดรูปทรง | อ่านจาก `gpkg_spatial_ref_sys` |
| CSV ที่มีพิกัด | `.csv` | Point เท่านั้น | ผู้ใช้ระบุ |

ขั้นตอนการนำเข้าแบ่งเป็น 4 ขั้น

1. **เลือกไฟล์** — ตรวจรูปแบบ ชนิดรูปทรง และความครบถ้วนของไฟล์ประกอบ
2. **ตรวจไฟล์และระบบพิกัด** — อ่านระบบพิกัดและการเข้ารหัสอักขระ (รองรับ TIS-620 สำหรับ `.dbf` ภาษาไทย)
   แล้วตรวจว่ารูปทรงต้นทางเข้ากับชั้นข้อมูลปลายทางหรือไม่
3. **จับคู่ฟิลด์** — จับคู่ฟิลด์ต้นทางกับชุดฟิลด์มาตรฐาน 21 ฟิลด์ กำหนดค่าตั้งต้นให้ฟิลด์บังคับที่ไฟล์ไม่มี
   และแปลงค่ารหัสให้ตรงตารางอ้างอิง
4. **ตรวจสอบและยืนยัน** — ตรวจคุณภาพด้วยกฎชุดเดียวกับหน้าตรวจคุณภาพข้อมูล แล้วบันทึกภายใน transaction เดียว

ข้อมูลที่นำเข้าจะมีสถานะ **ร่าง** และยังไม่เข้าชุดข้อมูลหลักหรือชุดเผยแพร่จนกว่าจะผ่านการอนุมัติ
ระบบแปลงรูปทรงให้ตรงชนิดของชั้นข้อมูลปลายทางอัตโนมัติด้วย `ST_Multi()` หรือ `ST_Dump()`
และแก้ไขรูปทรงที่ไม่ถูกต้องด้วย `ST_MakeValid()`

## เทคโนโลยีที่ใช้ในต้นแบบ

| ส่วน | เทคโนโลยี |
|---|---|
| หน้าจอ | HTML + CSS + JavaScript ล้วน ไม่ใช้เฟรมเวิร์กและไม่ต้อง build |
| แผนที่ | [Leaflet 1.9.4](https://leafletjs.com/) จาก CDN |
| แผนที่ฐาน | Esri World Light Gray Canvas · OpenStreetMap · Esri World Imagery |
| แบบอักษร | IBM Plex Sans Thai และ IBM Plex Mono จาก Google Fonts |
| ฐานข้อมูลที่ออกแบบไว้ | PostgreSQL 16 + PostGIS 3.4 (ดู `schema/postgis-schema.sql`) |
| API ที่ออกแบบไว้ | REST + OGC (ดู `api/openapi.yaml`) |

ต้นแบบนี้ไม่มีเซิร์ฟเวอร์และฐานข้อมูลจริง ข้อมูลเชิงพื้นที่บนแผนที่สร้างขึ้นในเบราว์เซอร์
ด้วยตัวสุ่มที่กำหนดค่าเริ่มต้นไว้ จึงได้ผลเหมือนเดิมทุกครั้งที่เปิด

**หากไม่มีอินเทอร์เน็ต** แผนที่ฐานและแบบอักษรจะโหลดไม่ได้ แต่หน้าจอทุกหน้ายังใช้งานได้
และชั้นข้อมูลบนแผนที่ยังแสดงผลตามปกติ

## ข้อควรทราบเรื่องขอบเขตงาน

ข้อกำหนดขอบเขตของงานฉบับที่ใช้เป็นต้นแบบระบุว่า การส่งมอบครอบคลุม **ฐานข้อมูลและไฟล์ส่งมอบ**
โดย **ไม่รวม** การพัฒนาระบบ Web GIS และการจัดซื้อเครื่องแม่ข่าย เว้นแต่ระบุเพิ่มก่อนประกาศจ้าง

ต้นแบบหน้าจอชุดนี้จึงมีสถานะเป็น **ข้อเสนอส่วนขยาย** เพื่อประกอบการพิจารณาว่าจะเพิ่มขอบเขตหรือไม่
หากไม่เพิ่ม ข้อกำหนดเดิมยังรองรับได้ด้วยการส่งมอบ GeoPackage และโครงการ QGIS
ซึ่งเป็นรูปแบบที่หน้า `export.html` อธิบายไว้
